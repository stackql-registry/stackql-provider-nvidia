# Engineering Notes

Phase 1 (2026-07-14) acquired and pinned the specs, verified the public-read posture on the wire, built the endpoint inventory and piloted the mapping. Phase 2 (2026-09-25) refreshed the toolchain (`@stackql/provider-utils` 0.7.10, `@stackql/pgwire-lite` 1.0.2, Docusaurus 3.10.2), converted the pipeline to `make`, resolved the response-schema gap in the harvested models definition, corrected the deprecation rule, added the org server template, the casing/pagination/pushdown wiring, the mock-backed integration suite, the offline validation, the tiered smoke suite, the docs microsite and CI. Live verification against an NGC organization is still owed (item 21).

Sibling findings reused, not re-derived: supabase (the project-scope server template with `x-stackQL-envVar`, root-path server overrides in post_process, the offline validation and mock-server integration layers, `--live` smokes, the weekly drift job), k8s (mock-first CI, the meta-route walk, `snake_case_aliases` + `nativeCasing`), clickhouse (org-scoped server template without a default), godaddy (path-level server templates with an env-var variable; the `kindOf` request transform), dockerhub (public-read classification), proxmox (EXEC returns a request id + status SELECT), vsphere (skip-with-notice gating), keycloak (PUT is not REPLACE without evidence), vercel (opaque body wrapper + transform).

## Resolved

1. **NVCF spec source - live.** `https://api.nvcf.nvidia.com/v3/openapi` (openapi 3.1.0, version 2.245.1, 35 paths / 54 operations), linked from https://docs.nvidia.com/nvcf/api. swagger-parser validates it clean. Pinned by sha256 in `spec_pin.json`.

2. **NGC harvest - usable; the explorer moved, the definitions did not.** In phase 1 the explorer at docs.ngc.nvidia.com/api/ was a swagger-ui over per-service definitions listed in its JS bundle. By 2026-09-25 the explorer is a hosted ReadMe site with no definition list in its pages, but the definition URLs the bundle declared still serve, and the NGC API definition is also served by the public gateway (`https://api.ngc.nvidia.com/v3/api-docs`, identical bytes to the internal host). `harvest_ngc_spec.mjs` now carries that catalogue as pinned URLs (with fallbacks) instead of scraping the bundle. Two in-scope definitions are publicly retrievable: `ngc_kas.json` (orgs/teams/users, v3.249.17, 77 paths, 102 operations, every one with a typed 2xx response) and `ngc_models.json` (registry and catalog artifact metadata, 232 paths, 334 operations). Five in-scope definitions (Org Mgmt, User IAM, Search, Metadata, Publishing) refuse public connections (the gateway answers 401 for the search and meta docs) - recorded in `download_manifest.json`.

3. **The models definition was response-less in July; the ngcsdk fallback covered the response side, and stays as the safety net.** The 2026-07-14 harvest declared no 2xx response on 303 of 333 models operations (4 `*Response` schemas in total); provider-utils `generate` refuses an operation without a 2xx, and a SELECT without a response schema projects nothing. The `ngcsdk` wheel on PyPI (4.36.6, sha256 `8cf4ce3b...`) ships auto-generated data classes for exactly this API (`registry/data/model/*.py`: `Model`, `ModelListResponse`, `ArtifactVersionFileListResponse`, `PaginationInfo`, ...; "auto-generated by main/tools/jsonparser"). `harvest_ngc_sdk_schemas.mjs` parses 149 classes into JSON Schema (typed property by property from the setter guards; enum modules skipped) and `clean_specs.mjs` merges the classes the definition lacks into `components.schemas` and attaches a 200 response to every response-less operation by an operationId rule (`SDK_RESPONSE_CLASSES`). The 2026-09-25 harvest of the same URL declares a 2xx response on every operation (127 schemas), so the rule now injects nothing and the vendor's own response schemas drive the mapping; the SDK derivation remains the recorded fallback (`spec_pin.json` `ngcSdk`, `download_manifest.json`) and `build_inventory.mjs` still fails on any SELECT method left on the bare `Response` envelope. Response naming differences between the SDK classes and the vendor schemas were absorbed by the objectKey rules (item 14).

4. **Gateway v1 -> v2 rewrite - applied in clean, confirmed by the SDK.** The models definition declares `/v1/...` on `models.ngc.nvidia.com`; the public gateway serves the same operations at `api.ngc.nvidia.com/v2/...` (phase-1 probes; the SDK's endpoint builders are `v2/org/{org}/models`, `v2/org/{org}/helm-charts/...`, `v2/artifact-registry/org/{org}/encryption-keys`, `v2/csps`; the Terraform provider's model URIs are `/v2/org/nvidia/team/nemo/models/...`). Rule `gateway-v2-path-prefix` rewrites 228 paths and the server.

5. **Public reads - wire-proven (phase 1).** Unauthenticated `GET /v2/models`, `/v2/models/{org}/{name}`, `/versions`, `/v2/recipes`, `/v2/resources`, `/v2/collections`, `/v2/gpus`, `/v2/{artifact_type}` return 200; org-scoped registry reads, `/v2/orgs`, `/v2/users/me`, `/v2/nvcf/*` return 401. The `/v2/gpus` body is a bare array (normalize wraps it). The provider's bearer config still requires `NGC_API_KEY` to be set for any query; any value works for the public reads (documented).

6. **Deprecation schedule - corrected in phase 2.** The authoritative page is https://docs.nvidia.com/ngc/latest/ngc-deprecated-api.html: on 2026-09-30 NVIDIA ends team-scoped (`/teams/{team}`) paths for NVCF, NVCT, FNDS, Skyway, SIS, SI, PYM, Infinity Manager and GDN, with the org-scoped replacement being the same path minus the segment; "products other than NVIDIA Private Registry and NVIDIA Data Services do not support team-level resource scoping". The phase-1 blanket skip of 141 team-scoped registry/org twins citing that schedule was therefore wrong: those families are exempt. Phase 2 maps them as `*_by_team` methods on the same resources (121 methods; `team_name` joins the required-parameter signature, so no verb overload clashes) and as `team_members` / `team_member_roles` / `team_invitations` resources in `orgs`. `SCHEDULED_DEPRECATIONS` in `build_inventory.mjs` encodes the page's families (none appear in the pinned specs today - the NVCF spec is `/v2/nvcf/...` without an org segment - but the rule is the build input); `check_deprecation_page.mjs` snapshots the page (`deprecation_schedule.json`, 86 path patterns) for the weekly drift job.

7. **NVCF paths: the published `/v2/nvcf/...` form is used, not the gateway's org-scoped form.** The Terraform provider and the deprecation page show `/v2/orgs/{org}/nvcf/functions/...` (and `/teams/{team}/` between) on the gateway; the published spec declares `/v2/nvcf/functions` and the NVCF docs use that form with a personal key. Both are served; the spec form needs no org and is what the pin documents. Switching is a one-line rebase rule if live use shows otherwise (item 21).

8. **Org scope as a server variable.** 204 org-scoped operations (orgs + private registry) are rebased by `bin/split.mjs` (prefix stripped, org path parameter dropped) and `post_process.mjs` attaches path-item `servers` templates (`https://api.ngc.nvidia.com/v2/org/{org_name}` etc.) with `org_name` carrying `x-stackQL-envVar: NGC_ORG`, no default. Verified offline (`org_name` leaves the required parameters when `NGC_ORG` is set) and against the mock (env value routes to `/v2/org/<NGC_ORG>/...`, a `WHERE org_name` value wins, unset with no `WHERE` fails with "cannot find any viable servers" - any-sdk's message, not one naming the variable). Root paths that keep an org parameter (`/v2/orgs/{org_name}`, `/v2/csps/{artifact_type}/org/{org_name}/...`) are ordinary path parameters. One host per service is validated by the inventory; `nvcf_queues` and `nvcf_invocation` sit on `api.nvcf.nvidia.com`.

9. **Reserved word.** `registry` cannot be a service name (`SHOW RESOURCES IN nvidia.registry` is a parser error - `REGISTRY` is a statement keyword). The service is `private_registry`.

10. **Definition defects repaired in clean, with a report** (`clean_report.json`): `ngc_kas` declares a relative server (`/`), 29 path parameters whose `name` is prose ("user id or b64encoded email") rather than the template token, one stray path parameter with no token, 16 query parameters with prose names ("Filter using org name" - wire names unknown, dropped) and 24 cookie parameters (`ncid`, `VisitorID`; any-sdk has no cookie location); `ngc_models` has 16 cookie parameters (`sc_cmp`) and camelCase / kebab-case path tokens used inconsistently (`{orgName}` and `{org-name}` for the same thing). Every path parameter is snake_cased in clean (provider-utils' split only converts the first hyphen per token).

11. **Mapping - green.** 498 operations inventoried (55 NVCF, 443 NGC core), 338 mapped (select 156, insert 64, update 42, delete 48, replace 4, exec 24), 160 skipped with reason codes (service-infra 24, internal-admin 34, deprecated-inline 44, superseded-by-v3-twin 4, non-generator-http-verb 7, data-plane-file-transfer 22, non-json-response 4, non-projectable-response 2, legacy-twin 3, duplicate-endpoint-family 15, inbound-webhook 1), 83 resources across 7 services (`catalog` 21, `nvcf_deployments` 7, `nvcf_functions` 7, `nvcf_invocation` 4, `nvcf_queues` 2, `orgs` 11, `private_registry` 31). The 2026-09-25 refresh (NVCF 2.245.1 -> 2.256.0 with a new `/info` endpoint, models definition with a new NIM metadata endpoint, collection shares deprecated inline) moved the counts from the phase-2 baseline of 347 / 149. Notable spec truths kept as-is: the typed models family has no DELETE (deletion rides `artifacts.delete` with `artifact_type = 'models'`, purge is `EXEC`); functions get/update/delete live on `function_versions` (the spec addresses a function by version); `authorizations` is grants-as-data (list `SELECT`, add `INSERT`, remove `DELETE`, set `REPLACE`, delete-all `EXEC`).

12. **Pagination.** NGC core lists declare zero-based `page-number` + `page-size`; `ngc_kas` responses carry `paginationInfo {index, size, totalPages, totalResults, nextPage}` and the SDK's `ModelListResponse` etc. carry the same object (undeclared in the models definition). any-sdk's `page_number` algorithm (linode/vercel precedent) follows `$.paginationInfo.index` / `$.paginationInfo.totalPages`: it requests page N after the last page N-1 and stops when the echoed index reaches the total, so the terminating request must return an empty page rather than an error - the mock does; the live behaviour is owed (item 21). 64 list methods carry the config plus `queryParamPushdown.top -> page-size` (no documented maximum, none set). NVCF lists are unpaginated. Verified against the mock: 5 rows over 3 pages of 2, `LIMIT 1` -> `page-size=1`.

13. **Casing.** `snake_case_aliases: true` on the provider; `request.nativeCasing` per method from the inventory (`camel` x225 for NVCF and JSON bodies, `kebab` x113 for methods with kebab query parameters). Verified against the mock: `resolve_labels = 'true'` -> `resolve-labels=true`; `display_name` -> `displayName` in POST/PATCH bodies. Docs render the wire spelling of kebab parameters (`page-size`); the engine accepts `page_size`.

14. **objectKey per response shape.** Lists unwrap their array property; entity reads unwrap their object property; when several qualify the property named after the resource wins (`modelVersion` for `model_versions`, `recipeVersion` for `resource_versions` via the trailing-segment rule, `artifactVersion` for `helm_chart_versions`). Entities with array fields (GPU catalog rows, `gpuCounts`) get none - the first rule tried used the array property and projected `column_anon`. The vendor types `GET .../license/acceptance` as the `requestStatus`-only envelope, so that read is skipped (`non-projectable-response`); the acceptance `POST` stays mapped.

15. **Transforms.** `function_ids.list` (`{functionIds: [string]}`) is re-shaped to `function_id` rows; `invocation_status.get` (typed as a byte buffer in the spec, really the function's own JSON) is wrapped into a `response` column; the pexec invocation body (lowered to an opaque string by normalize) is a `{body}` wrapper with a `kindOf`-guarded request transform - stackql hands a JSON-looking string argument to the template already parsed, so `toJson .body` is required (the `_raw: map[prompt:hello]` failure mode). All three verified against the mock.

16. **Integer-typed columns swallow non-numeric values, and the neighbouring columns too.** With the SDK's `ModelVersion.id` typed `long`, a mock that put "v1.0" in `id` made `SELECT id, status` return `id = 0, status = null` for the row while `SELECT *` was fine. The real wire has a numeric `id` and the string `versionId` ("use this instead of id" per the SDK) - the mock was corrected. Worth remembering when a typed column looks empty: check the wire type before the mapping.

17. **Terraform parity.** `NVIDIA/terraform-provider-ngc` (Go, 2024-, `ngc_cloud_function` + `ngc_cloud_function_telemetry`) reads `NGC_API_KEY`, `NGC_ORG`, `NGC_TEAM`, `NGC_ENDPOINT`. The provider uses the first three by name (`NGC_TEAM` only in the smoke suite - team scope is a per-query `team_name`). Its test template names the smallest instance it deploys with (`DGX-CLOUD.GPU.L40_1x` / `L40`) - the smoke suite picks the first instance type of the first cluster group instead.

18. **Auth error envelopes.** `api.ngc.nvidia.com` returns `{"requestStatus": {"statusCode": "UNAUTHORIZED", ...}}` with 401; `api.nvcf.nvidia.com` returns an empty 401 body. The mock reproduces both; the integration suite asserts the bearer header on every call and the 401 with a wrong key.

19. **Two key types.** The explorer exchanges a legacy NGC API key for a JWT (`authn.nvidia.com/token`, `Basic $oauthtoken:<key>`); personal API keys (`nvapi-...`) work directly as `Authorization: Bearer` per the NVCF docs and the Terraform provider. The provider assumes the direct-bearer personal-key path.

20. **The definition servers are not byte-stable.** Two fetches of the models definition seconds apart were canonically identical but differed in bytes (the `securitySchemes` scopes map, a Java map, serialises in a different key order each time), so a raw-byte pin drifted on the very next `make all`. The fetchers now write every download as canonical JSON (keys sorted recursively, arrays untouched - `lib/canonical.mjs`) and the pins hash those bytes; a pin drift therefore means real upstream change. NVCF 2.245.1 -> 2.256.0 and the models definition's new NIM endpoint were real changes accepted on 2026-09-25.

## Blocked on a key

21. **Live verification - owed once `.env` carries `NGC_API_KEY` / `NGC_ORG`.** `make smoke` covers: bearer acceptance on `orgs`, `current_user`, `users`, `teams`, registry models; the `page_number` pagination against a real multi-page collection (terminating request behaviour, `paginationInfo` present on registry lists); the kebab query parameters; a registry model INSERT / UPDATE / DELETE; NVCF enablement (cluster groups), fleet reads and an undeployed function INSERT / version get / authorizations / DELETE. `make smoke-nvcf` adds the deploy lifecycle (billable, gated, needs `NVCF_SMOKE_CONTAINER_IMAGE`). Also to confirm: whether `/v2/nvcf/...` or the gateway's `/v2/orgs/{org}/nvcf/...` form is right for a personal key (item 7), PUT field-drop semantics on `function_versions.update` and `artifacts.replace` (keycloak rule), and whether `GET /v2/csps` needs the Private Registry scope (phase-1 probe: 401).

## Open

1. **Catalog search** (`/v2/search/catalog/...`, wire-proven in phase 1) has no retrievable definition (the Search API host refuses public connections); the operation stays out until a definition materializes or the authenticated gateway probe (`api.ngc.nvidia.com/v3/search/api-docs`, 401 unauthenticated) succeeds with a key.
2. **`/v2/orgs` list filters** (`Filter using org name`, `...PEC ID`, ...) are declared with prose names; the wire parameter names are unknown, so the list is unfiltered on the wire (client-side `WHERE` still applies).
3. **`csps` writes** (`create`/`update`/`delete` on `/v2/csps`) and the GPU catalog writes are publisher-privileged; mapped as documented, untested.
4. **`orgs.orgs.get` keeps `org_name` as a path parameter** (the remainder after the org prefix is empty, so it cannot ride the server template) - it does not default from `NGC_ORG`.
5. **Docs casing for kebab parameters** - the generated docs show `page-size`; a sanitize-docs rule could present the snake spelling the engine accepts. Cosmetic.
